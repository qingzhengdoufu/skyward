# miro.15 - startup intro and first compatibility/safety repair batch

This is not full TWRP feature parity. Upstream version remains 0.2.0.

- Adds the approved 680 ms startup intro on ordinary miro Menu startup, driven
  by the normal event loop. Timing starts at the first loop frame. An input
  dismisses it without activating a hidden control. Special startup requests
  bypass it. r14 phone log observed 46 frames from 10.152s to 10.852s.
- EFS category cannot be selected when the device has no verified partition
  list, and the backend refuses an empty EFS selection. Does not guess or dump
  device identity/calibration partitions.
- Multi-part backup directories are exclusively created. A colliding timestamp
  cannot cause an existing backup to be reused or removed on failure cleanup.
- Backup manifests reject path traversal, duplicate partition/file entries,
  empty file lists and malformed digests before restore.
- simg2img accepts '-' for stdin, spooling up to 256 MiB in temporary storage
  before validating the sparse map and opening output. Large super images must
  use a file input, not this bounded spool. No multi-input resparse support.

Not added: encrypted backup, TWRP .win restore, ZIP install queue, full 7-Zip,
logical metadata resizing, boot/ramdisk GUI repacking, true panel-off touch wake
or fast-charge tuning. Full ROM install/real restore remain untested. Source
availability does not prove destructive workflows safe. See docs/TWRP-GAPS.md.

Only recovery_a is used for the authorized phone test. AVB unchanged, no ROM,
super/data/metadata write, format, erase, credential export or EFS read test.
Temporary tool tests use /tmp files. Existing recovery mounts/settings remain.
