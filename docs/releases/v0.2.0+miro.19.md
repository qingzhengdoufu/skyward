# Skyward 0.2.0+miro.19 - clear incorrect-password feedback

- Retain r18's signed update channel migration to qingzhengdoufu/skyward.
- Show a short localized "Incorrect password. Please try again." for explicit
  credential refusals on the data unlock page.
- Preserve service errors, throttling and storage errors without presenting
  them as wrong passwords. The runtime still logs the original error chain.
- Add regression tests for the localized message and unchanged error details.

No changes to credential verification, encryption, ZIP installation or AVB.
No deliberately incorrect credentials are submitted during device testing.

Install manually once from r17 or earlier to migrate the GitHub update channel.
r18 and r19 use the same release signing key. Only the current recovery slot
is targeted during the authorized device installation; no slot switch, system
flash or data formatting is part of it.
